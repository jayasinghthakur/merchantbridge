# M7 Resilience UI + activity (Tier 2, ~1/2 day)

**Goal:** every failure mode is demonstrable from the site, and real usage is visible on `/activity`.

**Read first:** `packages/core/src/telemetry.ts` (`DEMO_FAULTS`, `UsageEvent`, `TraceEvent`),
`packages/core/src/stores.ts` (`UsageStore.recent`, `deleteOlderThan`), `docs/adr/0005-*.md`, `docs/runbook.md`,
`apps/web/lib/faults.ts`, `apps/web/lib/trace.ts`.

**Tests first (red):**

- Each fault (`daily_quota_45`, `concurrency_1070`, `server_5xx`, `malformed`) produces the documented error code and
  governor decisions in the trace, for its session only.
- `/activity` API returns only the caller's tenant rows (demo: only demo rows), newest first, masked args only.
- `/metrics` exposes `mb_tool_calls_total{tool,status,error_code}`, `mb_tool_duration_seconds`,
  `mb_zoho_budget_remaining`, with no tenant names or ids as label values.
- Retention job deletes `usage_events` older than 30 days.
- stdio bin: spawned with `StdioClientTransport`, `tools/list` matches HTTP.
- Playwright: forced 429 shows the backoff step and a new `/activity` row within 5 s.

**Build:** remaining toggles in the playground UI, `/activity` page (table first; chart only if time allows),
`prom-client` `/metrics` (bearer-protected or private network), retention cron, `bin/merchantbridge-stdio`
(`serveStdio` from `@modelcontextprotocol/server/stdio`, demo tenant unless a key is provided).

**Out of scope:** alerts, dashboards beyond the table, OpenTelemetry.

**Done when:**

- `pnpm --filter @mb/api test && pnpm --filter @mb/web test && pnpm lint && pnpm typecheck` green.
- `pnpm --filter @mb/web e2e` (prod) passes the 429 -> `/activity` within 5 s check.
- `curl -s -H "Authorization: Bearer $METRICS_TOKEN" $API_URL/metrics | grep mb_tool_calls_total`.

**Commit:** `test(api): fault and activity contracts (red)`, `feat(web): resilience toggles`,
`feat(web): activity page`, `feat(api): metrics and stdio bin`.
