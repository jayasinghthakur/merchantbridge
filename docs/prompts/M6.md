# M6 Payments linker + Tier-2 tools (Tier 2, ~1 day)

**Goal:** Razorpay references resolve reliably to Zoho payments/invoices/orders, with a confidence; add
`zoho_check_stock` and `zoho_list_shipments`.

**Read first:** `docs/notes/zoho.md` §6.3, §6.6-6.8 and probes P-13, P-17-P-20 in ADR-0001, `docs/adr/0006-*.md`,
current `zoho_find_by_payment_reference` implementation and its evals, `packages/core/src/format.ts` (`toMoney`).

**Tests first (red, table-driven):**

- Classifier: `pay_`, `order_`, `rfnd_`, `sub_`, `plink_` ids (case, length, embedded in free text) and 12-digit UTRs
  (low confidence); false positives: phone numbers, invoice numbers, `pay_` inside URLs, 11/13-digit numbers.
- Money: paise <-> rupees for INR, 0-decimal and 3-decimal currencies; float edge cases (0.1 + 0.2).
- Search order: exact `reference_number` -> notes/custom fields (only fields smoke proved) -> bounded scan; returns
  `match: { via, confidence }`; scan bound respected and reported.
- `zoho_check_stock`: <= 25 item ids, SKUs rejected with a hint to use `zoho_get_item`.
- `zoho_list_shipments`: `/packages` `filter_by=Status.Shipped|Delivered`, response key `package`/`packages` both
  accepted, detail via `/shipmentorders/{id}`.

**Build:** `packages/zoho-inventory/src/payments/` (classifier, normalizer, resolver), wire into
`zoho_find_by_payment_reference`; the two new tools with FakeZoho fixtures, contract tests, 2 evals each,
`pnpm gen:tools`, CAN/CANNOT rows.

**Out of scope:** writing references back to Zoho, Razorpay API calls, conflict checks (Tier 3).

**Done when:**

- `pnpm --filter @mb/zoho-inventory test && pnpm lint && pnpm typecheck` green.
- `pnpm gen:tools && git diff --exit-code docs/mcp-tools.json` after committing the regenerated file.
- `pnpm evals` -> the Dispute Responder eval passes on Haiku.

**Commit:** `test(zoho): payment reference classifier table (red)`, `feat(zoho): payments linker`,
`feat(zoho): add zoho_check_stock`, `feat(zoho): add zoho_list_shipments`.
